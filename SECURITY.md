# Seguranca

## Comunicacao de vulnerabilidades

Nao publique vulnerabilidades criticas em issues publicas. Use o canal privado definido pela mantenedora do projeto antes da divulgacao publica.

## Politica

- Segredos reais nao devem ser versionados.
- Arquivos `.env` locais nao devem ser commitados.
- Dependencias devem ser revisadas periodicamente.
- Backups e restauracoes devem ser testados.
- Eventos relevantes devem gerar logs de auditoria.
- Integracoes entre servicos devem usar autenticacao apropriada.

## Triagem

Vulnerabilidades reportadas devem ser classificadas por severidade, impacto, explorabilidade e componentes afetados.

## Versoes suportadas

As versoes suportadas serao publicadas apos a primeira linha de releases do ecossistema.
